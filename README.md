# Amber — compile your agent's runs into programs

**Record an agent doing a workflow a few times; get a Python program that does it for a fraction
of the tokens, with replay tests, guards, a doctor for drift and a fallback to the agent.**

## Why

- Agents are great at *figuring out* a workflow and terrible at *repeating* it: every run
  re-spends a hundred thousand tokens or more re-deriving the same tool calls, nondeterministically.
- The idea is proven: FlashScript ([arXiv 2610.33876](https://arxiv.org/abs/2610.33876), Oct 2026)
  compiled agent trajectories into neuro-symbolic programs that reproduced the agent's tool calls
  with ~70× fewer input tokens and ~1/3 the runtime, and stayed correct where a skill-guided agent
  degraded. No code was released.
- Amber is an open, harness-agnostic implementation with what production needs around it:
  replay tests generated from the recordings, guards on every live call, a doctor that detects
  drift, and a fallback that hands the task back to the agent and recompiles.

Caches replay the past; skills instruct the agent; Amber compiles what the agent learned into a
program you can read, test and run — and hands control back to the agent only when the world
changes.

## Install

```bash
git clone https://github.com/enestanerr/Amber && cd Amber
uv sync --all-extras && uv run amber --version          # amber 0.1.0
# or build the wheel and install the CLI as a tool:
uv build && uv tool install dist/amber_compiler-0.1.0-py3-none-any.whl
```

`uv tool install amber-compiler` works once the package is on PyPI (not published yet). Amber
needs Python 3.12+ and either a logged-in `claude` CLI or `ANTHROPIC_API_KEY`. A claude.ai
subscription is enough: recordings, hole synthesis and run-time `llm()` calls all go through
`claude -p`. The price-watch example also needs Node ≥ 18 (`@playwright/mcp`).

## The 60-second story (6 commands)

```bash
cd examples/weekly-report
make record                            # 3 × `amber record … -- claude -p "<task>" --model claude-sonnet-5-5`
amber align weekly-report --show       # the skeleton: steps, provenance, judgment vs deterministic
amber compile weekly-report            # program.py + manifest + replay tests; verify 3/3 → usable
amber verify weekly-report             # replay every recording (exit 3 on divergence)
amber run weekly-report --input week=2026-W40 --allow-writes   # live, 0 agent turns, 1 llm() call
amber doctor weekly-report             # drift report + recommendation (exit 5 unless healthy)
```

Real output for every step, and the drift → doctor → fallback → recompile loop, is in
[docs/user/quickstart.md](docs/user/quickstart.md). No `claude` at hand? `make demo-offline`
runs the same pipeline on the synthetic fixture recordings with recorded model fills.

## How it works

```mermaid
flowchart LR
  R[record<br/>claude -p · transcripts · Agent SDK · MCP proxy] --> T[(traces)]
  T --> A[align<br/>sequence alignment · provenance · classify · prune]
  A --> C[compile<br/>deterministic codegen · typed holes filled by the model]
  C --> V[verify<br/>cassette replay of every recording]
  V --> P[(programs/vN<br/>program.py · manifest · tests · REPORT)]
  P --> X[run<br/>guards · ledger · llm() for judgment only]
  X --> D[doctor<br/>schema & shape drift · stats]
  D -->|fallback| F[agent resumes from the failed step]
  F -->|new trace| A
```

1. **record** — adapters turn Claude Code stream-json, Claude Code transcripts, Agent SDK
   messages or any MCP client (through `amber proxy`) into one canonical trace format.
2. **align** — several runs become a skeleton: each argument gets a provenance
   (`Input`, `Ref` to an earlier result, `Template`, `Const`, or `Unknown`), each step a kind.
3. **compile** — the structure is generated by code; the model only fills typed holes
   (transform functions, judgment prompts + schemas, gates), and every fill is checked against the
   recordings with a bounded repair loop. A transform the model cannot write becomes a judgment.
4. **verify** — a cassette backend replays each recording; every call must match in order.
   A program that fails replay is not a program.
5. **run** — live MCP calls with a tool allowlist, budgets, result-shape checks, write-effect
   dry-run by default, and small schema-validated `llm()` calls for the judgment steps.
6. **doctor / fallback** — drift is detected (schema hashes, result shapes, guard statistics),
   diagnosed, and if needed the agent resumes from the failed step; `compile --refresh` folds the
   new run in.

The principle throughout: **deterministic compiler, typed holes.**

## What comes out

`programs/weekly-report/v2/program.py` as compiled from three live recordings plus one fallback
run (trimmed; the prompt constant and Output model are left out):

```python
class Inputs(BaseModel):
    week: str = Field(description="Declared input", examples=["2026-W42", "2026-W43", "2026-W44", "2026-W41"])

# AMBER-HOLE:transform_step1 — transform for shop.week_range (week)
def transform_step1(inputs: dict[str, Any], r0: Any) -> dict[str, Any]:
    m = re.match(r"^(\d{4})-W(\d{1,2})$", str(inputs["week"]).strip())
    y, w = int(m.group(1)), int(m.group(2))
    monday = datetime.date.fromisocalendar(y, w, 1) - datetime.timedelta(days=7)
    iy, iw, _ = monday.isocalendar()
    return {"week": f"{iy}-W{iw:02d}"}

# AMBER-HOLE:judgment_step6 — judgment for slack.post_message (channel, text)
class Step6Out(BaseModel):
    channel: str = Field(description="Slack channel to post to, default 'eng'")
    text: str = Field(description="The weekly report paragraph")
    confidence: float = Field(description="Confidence 0..1")

@program(workflow="weekly-report", version=2)
def run(inputs: Inputs, ctx: Context) -> Output:
    r0 = ctx.tool("shop.week_range", week=inputs.week)  # step 1
    t1 = transform_step1(inputs.model_dump(), r0)  # transform hole
    r1 = ctx.tool("shop.week_range", week=t1["week"])  # step 2
    r2 = ctx.tool("shop.list_orders", since=r0["start"], until=r0["end"])  # step 3
    r3 = ctx.tool("shop.rfm_snapshot", as_of=r0["end"])  # step 4
    r4 = ctx.tool("shop.rfm_snapshot", as_of=r1["end"])  # step 5
    r5 = ctx.tool("shop.top_products", n=5, since=r0["start"], until=r0["end"])  # step 6
    s6 = ctx.llm("step6", Step6Out, PROMPT_step6, context={"inputs": ..., "r2": r2, "r3": r3, "r4": r4, "r5": r5})
    r6 = ctx.tool("slack.post_message", channel=s6.channel, text=s6.text)  # step 7  # effect: write
    return Output(ok=r6["ok"], ts=r6["ts"], channel=s6.channel, text=s6.text)
```

`REPORT.md` lists the skeleton, every hole fill with its rationale, the verify table and a
"review before live" note.

## Measured

From [bench/results.md](bench/results.md), a live run on 2026-11-02: claude CLI 2.1.316 on a
claude.ai subscription, agent `claude-sonnet-5-5`, compiled judgments `claude-haiku-5-5`. The
baseline is each example's three live recordings; the compiled program ran once per recording
with the same inputs and scenario, against the synthetic mock servers.

| example | agent tokens (median) | compiled llm tokens (median) | ratio | agent $ | compiled $ | agent wall s | compiled wall s | llm calls | fidelity exact / core | agent turns |
|---|---|---|---|---|---|---|---|---|---|---|
| issue-triage | 153,944 | 11,892 | 12.9x | 0.087 | 0.003 | 15.3 | 10.3 | 1 | 67% / 100% | 0 |
| price-watch | 165,225 | 14,862 | 11.1x | 0.071 | 0.003 | 21.5 | 11.4 | 2 | 100% / 100% | 0 |
| weekly-report | 174,076 | 29,472 | 5.9x | 0.170 | 0.008 | 28.9 | 33.6 | 1 | 0% / 100% | 0 |

Read it with these in mind:

- Three recordings and three compiled runs per example is a small sample on synthetic data.
- Agent tokens are mostly cache reads of Claude Code's own context. `$` is the API-equivalent
  cost the CLI reports; a subscription is not billed per call.
- The compiled judgments run on Haiku while the agent ran on Sonnet, so part of the cost gap is
  the model choice.
- weekly-report's compiled run is not faster: its one judgment thinks for about 25 s while it
  counts 240 RFM rows. It does count them correctly, which a recount from the data confirmed.
- *Exact* fidelity compares the whole tool sequence with the recording. It is below 100% where
  the agent made exploratory reads that the program drops (a channel lookup, an extra issue
  list). *Core* fidelity ignores those pruned reads.
- FlashScript's ~70× is the paper's number, not Amber's.

## Tested live

On 2026-11-02 every example went through record → align → compile → verify → run with the
`claude` CLI. The weekly-report drift loop ran end to end: the drifted run stopped on a guard,
the doctor recommended fallback, the agent resumed from the failed step, and `compile --refresh`
produced a v2 that verified 4/4 and ran healthy. The live runs exposed more than twenty problems
that the synthetic fixtures had hidden. Each fix is its own commit, every code fix has a regression
test, and [PROGRESS.md](PROGRESS.md) lists them.
price-watch's spec'd drift (renaming the `.price` CSS class) does not break the compiled program
at all, because Playwright MCP's accessibility snapshot never contains CSS classes; the
self-healing demo therefore uses weekly-report.

## Supported inputs

Claude Code (`claude -p`), Claude Code transcripts (`amber import --latest`), the Claude Agent
SDK (`--sdk`), and any MCP client through `amber proxy` + `amber import --proxy`.
Roadmap: OpenAI Agents SDK, OpenTelemetry GenAI spans.

## What it can't do yet

- Loops and pagination are not collapsed: per-item calls (one `add_labels` per issue) stay
  separate steps and cannot serve a different count. Batch tools work: a list argument whose
  length varies is filled by one hole. issue-triage's mock server uses batch writes for this
  reason.
- Judgment holes produce strings, numbers, booleans and string lists; a structured batch value
  must come from a transform.
- Alternative ways to reach the same data (navigate-and-snapshot in one run, a JavaScript fetch
  in another) become separate conditional steps. Keep recording tasks tight.
- No parallel steps; no multi-agent traces (sidechains are skipped).
- Only a safe subset of Claude Code builtins (`Read`, `Write`, `Glob`, `Grep`, `WebFetch`, a
  template-locked `Bash`); others are a compile-time error.
- No hosted runner, no approval UI for writes (dry-run by default, `--allow-writes` to execute).
  Browser navigation counts as a write, so price-watch needs `--allow-writes` even to read.
- TypeScript program output is a roadmap item; programs are Python only.
- The live runs were on Windows 11; CI runs the test suite on Ubuntu and macOS.

## Related work

- [muscle-mem](https://github.com/pig-dot-dev/muscle-mem) — a behaviour cache that replays one
  recorded path when environment checks pass; Amber compiles *several* runs into a parameterised
  program with typed `llm()` steps, replay tests and a drift loop, without instrumenting your agent.
- [FlashScript](https://arxiv.org/abs/2610.33876) — the research result Amber implements in the
  open, with adapters and an operating loop.
- taprun — records browser workflows and replays them (closed, browser-only); Amber works on any
  MCP tool and emits code you own.
- Codex "Record and Replay" — drafts a SKILL.md from a session; Amber emits an executable program
  with tests and guards.
- Claude Code skills / hooks — complementary: a skill tells the agent how; Amber removes the agent
  from the loop for the repeatable part.
- VCR-style cassette libraries — the same idea applied to MCP tool calls, plus volatility masking
  and `llm()` recording.
